# Exposure Watch

Лёгкий сканер публично доступных конфигов, Git-файлов, SQL-дампов и служебных страниц. Работает на Linux/VPS без Python-зависимостей. Python 3.11+.

## Возможности

- 13 фиксированных путей: `.env`, `.env.production`, `.env.local`, `.git/HEAD`, `.git/config`, `backup.sql`, `dump.sql`, `phpinfo.php`, `info.php`, `server-status`, `backup/`, `backups/`, `uploads/`.
- Структурные сигнатуры содержимого вместо вывода по одному HTTP-коду.
- Два случайных несуществующих пути для отсечения soft 404 и wildcard-ответов.
- Повторный запрос перед сохранением находки.
- Строго заданные origins; редиректы не переходятся, поддомены не добавляются.
- Последовательные запросы с паузой; при 429/503 проверка текущего origin заканчивается, следующий цикл — по расписанию. После серии сетевых/серверных ошибок origin пропускается.
- JSON/Markdown-отчёты, SQLite-история и отметка новых находок.
- Полные тела ответов и значения секретов не сохраняются. Чтение ответа ограничено 64 КиБ по умолчанию. Значения не проверяются у внешних провайдеров.
- Работа разово или по расписанию, блокировка параллельного запуска с одной папкой данных, очистка старых JSON-отчётов.

## Установка на VPS через Docker

Нужны Linux и установленный Docker с Compose v2. Скопируй архив на VPS, распакуй и зайди в папку `exposure-watch`.

```bash
cp config.example.json config.json
nano config.json
```

В `targets` укажи точные origins из разрешённого scope. Поддомены перечисляй отдельно; схемы HTTP и HTTPS тоже считаются разными origins. Если программа требует идентификационный User-Agent, укажи его в конфиге. Не добавляй в URL токены или пароли.

```json
{
  "targets": ["https://app.your-domain.example", "https://api.your-domain.example"],
  "request_interval_seconds": 1,
  "timeout_seconds": 10,
  "interval_hours": 24,
  "max_body_bytes": 65536,
  "max_consecutive_errors": 3,
  "retention_days": 30,
  "user_agent": "ExposureWatch/1.0 (authorized security testing)"
}
```

После редактирования:

```bash
mkdir -p data
sudo chown 10001:10001 data
chmod 600 config.json
sudo chown 10001:10001 config.json
sudo docker compose up -d --build
sudo docker compose logs --tail=50 -f
```

Первый проход начнётся сразу. Следующий — через 24 часа после завершения предыдущего. Процесс перезапускается Docker после сбоя/перезагрузки VPS, если Docker запускается при загрузке системы. Отдельный cron не нужен. Публичные порты открывать не требуется. Нужны исходящий HTTP(S) и DNS.

Отчёт:

```bash
sudo cat data/latest.md
sudo cat data/latest.json
sudo docker compose stop
```

После изменения списка целей перезапусти сервис: `sudo docker compose restart`. Watch-режим также перечитывает конфиг перед очередным проходом.

## Разовый запуск без Docker

```bash
cp config.example.json config.json
nano config.json
python3 scanner.py --config config.json --data data
```

Непрерывная работа: `python3 scanner.py --watch`. Для постоянной работы используй Docker или системный менеджер процессов. Не запускай одновременно Docker и локальную версию на одной папке данных.

## Результаты и ограничения

`latest.json` содержит `findings` и `events`. `new: true` означает, что сочетание URL/проверки раньше не сохранялось. Это не оценка критичности. Все результаты имеют `classification: review_required`: публичный directory listing или тестовый конфиг могут быть допустимыми, а `.git/HEAD` сам по себе ещё не доказывает возможность скачать репозиторий.

Сканер не краулит сайт, не ищет поддомены и не исследует произвольные имена резервных копий. Авторизация, API-проверки, автоматическая отправка отчётов в программы и уведомления не реализованы. Нет WAF-bypass, обхода CAPTCHA или автоматического использования найденных секретов. Отсутствие находок означает только отсутствие совпадений в этих проверках. JSON-события показывают недоступные и ограничившие запросы origins; они не считаются успешно проверенными.

Тела ответов остаются только в оперативной памяти до обработки. Отчёты содержат адреса целей, поэтому папку `data` тоже следует считать приватной. История URL хранится в SQLite без автоматического удаления; JSON-отчёты удаляются через `retention_days`.

Ориентир ресурсов для этого последовательного сканера: 1 vCPU и 512 МиБ RAM без учёта ОС. Фактическая нагрузка зависит от ответов целей. Браузер не используется.

## Проверка

```bash
python3 -m unittest discover -s tests -v
```

Тесты запускают локальный HTTP-сервер. Проверяются реальные HTTP-запросы, soft 404, запрет переходов по редиректам, остановка на 429, повторное подтверждение, история и отсутствие значений секретов в отчётах. Никакие внешние сайты в тестах не сканируются.

Локальная конфигурация `config.json` и результаты в `data/` исключены из Git.
