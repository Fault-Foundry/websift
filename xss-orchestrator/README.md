# XSS orchestrator: Katana + gau + Dalfox

Bash-оркестратор для Linux VPS. Сам XSS-движок не написан заново: разведку выполняют готовые Katana/gau, поиск отражений и статический анализ DOM XSS — Dalfox. Python здесь только разбирает URL, проверяет scope и раскладывает отчёты, сетевых запросов в glue.py нет.

Закреплённые версии: **Dalfox 3.2.4, Katana 1.8.0, gau 2.2.4**. Старые команды и флаги Dalfox v2 не подходят. Установщик загружает бинарники из официальных GitHub Releases и сверяет опубликованные SHA-256. Linux amd64/arm64, Python 3.9+, Bash, curl, flock, timeout; root не нужен. Начальная практичная конфигурация VPS: 2 vCPU, 4 ГБ RAM, диск под результаты. Это ориентир, а не измеренный минимум.

## Быстрый запуск

Распаковать архив в рабочую папку и перейти в `xss-orchestrator`:

```bash
bash install.sh
export PATH="$PWD/bin:$PATH"
cp -r example my-program
nano my-program/origins.txt
nano my-program/exclude.txt
bash run.sh my-program recon
```

`origins.txt`: по одному **точному разрешённому origin** на строку, например `https://app.example.com`. Схема и нестандартный порт учитываются. Никаких неявных wildcard: `app.example.com` не разрешает `other.example.com`. Origin должен быть без пути. Если правила программы ограничивают пути, внеси все такие исключения в `exclude.txt` до запуска. Исключения внутри Katana/Dalfox применяются к URL в представлении самого инструмента; для path-scope учитывай также percent-encoding. Для сложного scope, который не получается точно выразить этим способом, эту цель в список не добавляй.

`seeds.txt`: необязательные начальные страницы; пустой файл означает корни origins. `urls.txt`: необязательные URL из Burp или предыдущего обхода. `exclude.txt`: исключения в виде regex по полному URL; синтаксис, совместимый с Go/Rust/Python, без lookaround и backreferences. Пример ограничения к одному префиксу лучше задавать отдельным разрешённым origin только если весь этот origin действительно разрешён — whitelist путей этой версией не реализован.

После разведки скрипт покажет каталог запуска. Просмотри `allowed.txt`, `inputs.tsv`, `query_targets.txt`, `reflected.txt`, `dom.txt`, `rejected.jsonl`. Затем передай **этот каталог**, например:

```bash
bash run.sh my-program scan /absolute/path/to/my-program/runs/20261108T120000Z-ABC123
```

Путь выше — пример; используй фактический путь из вывода. Один вызов для обоих этапов:

```bash
RPS=2 PASSIVE=1 bash run.sh my-program all
```

`PASSIVE=1` добавляет URL из Wayback/Common Crawl через gau. Архивы по умолчанию выключены: запрос к архиву раскрывает его оператору интерес к имени хоста. `gau` не включает поддомены автоматически. Все полученные URL проходят фильтр перед активным запросом. Не используй последнюю команду до замены примеров своими разрешёнными целями.

## Как проходит разведка

1. Точный список origins и исключений фиксируется копией внутри каталога запуска.
2. Начальные URL, экспортированные URL и необязательные архивные URL проходят scope-фильтр. URL с userinfo, чужим origin/портом, обратными слешами и управляющими символами отклоняются.
3. Katana обходит разрешённые страницы и разбирает ссылки в JS. Используется обычный HTTP-режим, redirects выключены, глубина 3, одна параллельная цель, лимит 2 запроса/с. Headless не включён: загрузка браузером сторонних ресурсов потребовала бы дополнительного сетевого контроля.
4. Результаты снова проходят scope-фильтр; удаляются точные дубли и явно статические расширения изображений, шрифтов, архивов и т. п. JavaScript не выкидывается по имени файла. Файл `rejected.jsonl` хранит причины отбраковки. Фильтр расширений эвристический: перепроверь его для нестандартных приложений.
5. Сохраняются настоящие значения query, порядок повторяющихся ключей, пустые значения и hash-маршруты. `inputs.tsv` содержит обнаруженные query-входы и страницы для дальнейшего поиска имён input. Это инвентаризация входных кандидатов, а не список доказанных уязвимостей.
6. Dalfox в reflected-проходе проверяет query-входы, а также выполняет HTML input-name mining на страницах без query. Словарный mining выключен, header/cookie/path injection выключены. Не все найденные HTML inputs соответствуют рабочему GET-параметру: это проверяет движок.
7. Отдельный DOM-проход получает **все** оставшиеся страницы, включая страницы без query. Dalfox анализирует inline JS и доступные same-origin внешние скрипты. Для этого прохода нет предпосылки «параметр отражается в HTTP», иначе DOM XSS из `location.hash` потерялся бы.

Предварительный `kxss | dalfox` специально не сделан обязательным шлюзом: он дублирует часть анализа Dalfox и может отсечь DOM XSS без серверного отражения. `gf xss` тоже не используется как окончательный фильтр — название параметра не определяет его уязвимость. `httpx` не нужен как обязательный шлюз перед каждым URL: Dalfox и Katana сами выполняют HTTP-запросы; жёсткий фильтр только по `200` потерял бы полезные страницы.

Поддомены можно искать отдельно существующим **subfinder**, если scope действительно разрешает их поиск. Но результат перечисления — лишь кандидаты. Не превращай автоматически каждый найденный хост в разрешённую цель; сначала сопоставь с правилами программы и внеси подходящие origins. Этот пакет начинает работу с уже определённого списка разрешённых приложений.

## Отчёты и ложные срабатывания

| Файл | Что означает |
|---|---|
| `strong_candidates.json` | Не-AST находки Dalfox с типом V: сильное статическое подтверждение, нужна проверка браузером |
| `dom_candidates.json` | Находки с `detection_method=ast`, независимо от V/A: возможный source → sink |
| `reflections.json` | Тип R: отражение payload без доказанного исполняемого контекста |
| `other.json` | Остальные результаты, сохранены для разбора |
| `reflected.json`, `dom.json` | Полные исходные отчёты движка |
| `metadata.json`, `*.exit`, `*.log` | Пропущенные цели, неполные проверки, ошибки и диагностика |
| `summary.txt` | Итог и количество результатов по категориям |

**Dalfox v3 не запускает Chrome. V не означает, что JavaScript выполнился.** В пакете нет автоматического браузерного подтверждения, поэтому файл «подтверждённые баги» намеренно не создаётся. Отражения сохраняются отдельно и не объявляются XSS.

Последний этап для отчёта в bounty: открыть точный PoC в чистом профиле браузера на разрешённой цели, воспроизвести нужные действия и убедиться в выполнении JavaScript в контексте приложения с действующей CSP. Для DOM удобно использовать **Burp DOM Invader**, чтобы проверить управляемость source, достижимость sink и требуемые действия. Зафиксируй URL/запрос, параметр или source, шаги, фактическое поведение и влияние. Сам факт наличия `innerHTML` в JS или отражённой строки отчётом не является. DOM Invader здесь указан для ручного подтверждения, он не интегрирован в автоматический запуск.

Код завершения оркестратора: `0` — обработка завершилась (находки могут быть), `2` — ошибка подготовки/инструмента, `3` — скан неполный или отчёт не читается. В отличие от Bash `set -e` напрямую поверх Dalfox, код Dalfox `1` здесь считается успешным запуском с находками. Даже если Dalfox вышел с `1`, флаг `meta.incomplete` и статусы skipped/incomplete проверяются отдельно. Таймаут не превращается в «чисто».

## Возможности и ограничения

Оркестратор проверяет публичные GET-страницы на reflected XSS и собирает статические DOM-кандидаты. Stored/blind режимы, OAST, автоматическое заполнение форм и обход WAF не включены. GET сам по себе не гарантирует отсутствие изменения состояния на плохо спроектированном приложении. Добавь специфичные для программы исключения до обхода.

Не покрыты автоматически: авторизация, POST/JSON/GraphQL тела, сложные SPA-переходы и lazy chunks, postMessage-сценарии с несколькими окнами, persistent browser state, runtime-подтверждение DOM, логика бизнес-процессов. Не передавай секреты через `urls.txt`. Для закрытой части приложения сначала нужны отдельные конфигурации сессии, разрешённых путей и сырые запросы из Burp; этот пакет такие запросы не импортирует.

Отбор не удаляет `403`, `404`, `429` как класс. Сканер может отметить неподходящие ответы как skipped; такая цель требует разбора и даёт неполный итог. Бесконечные календари, уникальные tracking-query и огромные архивы способны раздуть очередь: ограничивай `seeds.txt`, исключения и время. Автоматической классификации soft-404 и определения всех crawl traps здесь нет.

Лимиты меняются через окружение: `RPS=2`, `WORKERS=2`, `DEPTH=3`, `CRAWL_SECONDS=300`, `STAGE_SECONDS=7200`. Этапы последовательные, поэтому лимиты Katana и Dalfox не складываются; сторонний трафик ОС и обращения gau к архивам ими не регулируются. `STAGE_SECONDS` — внешний жёсткий лимит каждого этапа, не всего запуска. Его превышение делает запуск незавершённым. Повторный scan в том же каталоге заблокирован, чтобы не перезаписать результат. Для нового прохода запускай новую разведку; свежий каталог позволяет перепроверить прежние endpoints после обновления приложения.

Для работы на VPS в отдельной терминальной сессии:

```bash
tmux new -s xss
export PATH="/absolute/path/to/xss-orchestrator/bin:$PATH"
bash /absolute/path/to/xss-orchestrator/run.sh /absolute/path/to/my-program all
```

Отсоединиться: `Ctrl+B`, затем `D`; вернуться: `tmux attach -t xss`. Запускай от обычного пользователя. Сервис и открытый порт для Dalfox не нужны. Не ставь непрерывный перескан той же очереди без изменений: полезнее дополнять входы и перепроверять после изменений приложения. Храни каталог результатов с правами только для своего пользователя.
