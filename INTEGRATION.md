# Технические заметки

Краткий обзор проекта — в [README.md](README.md).

## Общая разведка и запуск

`python bot.py` — бот. `shared_recon.py` управляет сессиями и разведкой, `scan_pipeline.py` — проверками и статусами. Старый независимый запуск Katana из SQLi заменён адаптером к общему слою.

Для каждой цели создаётся отдельный ReconService. Результат кешируется в пределах этого запуска по идентификатору сессии, cookies и headers. SQLi и XSS используют один результат A; IDOR получает отдельно A и B. Сканеры могут выполнять собственные запросы проверки: общий обход не означает, что каждую страницу посетят только один раз.

## Выбор режима

Установите в `.env`:

```dotenv
RECON_MODE=http
```

- `http`: HTML-ссылки, формы, статический поиск адресов в доступных JS; Katana не запускается.
- `js`: дополнительно Katana с cookies той же сессии и ограничением origin.
- `browser`: Katana с `-headless`. Требует Chrome/окружения Katana. Это браузерное обнаружение URL, не полноценная запись всех API-запросов, тел и пользовательских сценариев.

Автоматического безошибочного определения SPA нет. Для обычного сайта начните с http, для JS-маршрутов — js, для динамического исполнения — browser. Недоступный выбранный инструмент даёт incomplete, а не успешный пустой результат. Scope-флаги браузерного обхода не являются сетевой изоляцией сторонних ресурсов Chrome.

`RECON_TIMEOUT=300` ограничивает Katana. `KATANA_BIN` переопределяет бинарник. Старый `KATANA_ENABLED` больше не используется.

## Авторизация

В чате `-` означает анонимную проверку, `defaults` — учётные записи из DEFAULT_USER_A/DEFAULT_PASS_A и B, `user:pass` задаёт аккаунт явно. Пароли по умолчанию больше не показываются в чате. IDOR требует две разные проверенные сессии.

Для обычного HTML-входа достаточно URL и учётных данных в Telegram. AUTH_* не обязательны. Поиск проверяет начальную страницу/редиректы, ссылки входа на сайте и типовые адреса относительно каталога приложения и корня origin (до 24 страниц). Неоднозначные формы, регистрация и смена пароля не отправляются автоматически.

Форма загружается и отправляется в одной сессии с CSRF и submit-полями. После входа повторный GET сравнивается с отдельной анонимной сессией: нужен переход от запрета/формы входа к доступу либо появление элемента выхода только под сессией. Одна cookie, изменение текста или отсутствие password-поля успехом не считаются. Это эвристическая проверка, а не универсальное доказательство личности.

AUTH_LOGIN_URL, AUTH_CHECK_URL и AUTH_SUCCESS_REGEX остаются необязательными подсказками для сложного стенда. Если вы ранее добавили их только по примеру DVWA, удалите эти строки для автоматического режима. При явном маркере он проверяется вместо автоматической эвристики. При неоднозначном входе бот сообщает причину и не продолжает как анонимный пользователь.

SPA-вход через браузер и восстановление localStorage/sessionStorage реализованы в browser_auth.py; требуется Playwright. OAuth/SSO между origin, MFA/CAPTCHA и произвольные многошаговые сценарии не поддержаны. HTML-сессии сохраняют cookie jar с domain/path; HTTP-заголовок для SQLi строится для конкретного URL. Браузерный экспорт пока отклоняет одноимённые cookies разных областей. AUTH_* подсказки общие для процесса; без них адрес входа определяется отдельно для каждой цели.

## Проверки

- SQLi использует найденные query и формы под A. `/sqli` обходит сайт и при наличии query в начальном URL; `/sqli_check` проверяет одну точку. Ошибки/таймауты отделены от отсутствия находок.
- XSS импортирует разрешённые URL общей разведки и cookies A, затем запускает Dalfox; повторной Katana нет. POST-формы не передаются как готовые захваченные запросы; сохраняется URL-oriented режим инструмента друга. Частичные отчёты сохраняются, кандидаты требуют браузерной проверки.
- IDOR выполняет GET по наблюдавшимся адресам с числовыми ID/UUID; сохраняет исходный query. Сравнивает содержимое объекта под A/B и анонимно, исключает одинаковые общие страницы. Находки — кандидаты с непроверенным владением/политикой доступа. Динамические ответы могут не совпасть и дать пропуск. POST/JSON mutations, предположения об ownership и старые обходные эвристики удалены.

Статусы: completed, incomplete, error, skipped. Completed означает завершение настроенной проверки, не доказательство безопасности. Пределы обхода остаются max_pages=50/max_depth=3; весь сайт и все браузерные действия не гарантируются.

`RECON_EXCLUDE_REGEX` задаёт исключения обхода. По умолчанию исключены типовые logout/delete/reset/setup пути. `XSS_EXCLUDE_REGEX` может дополнить/переопределить исключения XSS. Regex должен быть совместим с Python/Go/Rust; inline flags используйте внутри группы `(?i:...)`.

## Инструменты и артефакты

Локальный xss-orchestrator/bin/dalfox проверен: 3.2.4. Системный Dalfox может оставаться старой версии; используется локальный. Установка локальных закреплённых версий:

```bash
bash xss-orchestrator/install.sh
```

`SCAN_OUTPUT_DIR` — каталог XSS-артефактов (по умолчанию scan_output). Сессионный входной файл удаляется после сканирования; исходные отчёты Dalfox могут содержать запросы с cookies. Каталоги приватные, очистка вручную.

IDOR CLI: `python -m IDOR.idor_orchestrator --help` (также работает путь IDOR/idor_orchestrator.py). Старые аргументы cookie-a/cookie-b заменены проверяемым входом через общий слой.

Живой Telegram, sqlmap, Dalfox 3.2.4 и браузерный SPA-обход не проверены.


## SPA: автоматический браузерный вход

По умолчанию `AUTH_MODE=auto`: сначала обычная HTML-форма, при отсутствии подходящей формы — браузер. Неверный пароль после отправки HTML-формы не вызывает повторную попытку в браузере. Для известных SPA с HTML-оболочкой формы можно явно поставить `AUTH_MODE=browser`; `AUTH_MODE=html` запрещает fallback. Пути входа по умолчанию не нужны.

Установка в Python-окружение бота (создана .venv с system-site-packages):

```bash
.venv/bin/python -m pip install -r requirements-browser.txt
.venv/bin/python -m playwright install chromium
.venv/bin/python bot.py
```

Существующий google-chrome/chromium выбирается автоматически, поэтому установка Chromium необязательна при совместимом системном браузере. `BROWSER_EXECUTABLE` — необязательное переопределение пути. `BROWSER_AUTH_TIMEOUT` по умолчанию 90 секунд.

Браузер использует отдельный непостоянный контекст на аккаунт, блокирует запросы за пределы origin и service workers. Ищет видимое поле пароля, email/username и кнопку входа через ссылки/меню. Выполняет одну отправку, затем перезагрузку. Authorization извлекается только из наблюдавшихся успешных API GET-запросов, а не из произвольного ключа localStorage. Перенесённая сессия проверяется HTTP-запросом к наблюдавшемуся API отдельно от гостя. Для JSON-identity ответа проверяются email/username/login. Появление произвольного токена или изменение SPA-оболочки недостаточно.

Cookies и Authorization передаются во все детекторы. XSS получает приватный config JSON, который удаляется после сканирования. localStorage/sessionStorage хранятся в памяти и восстанавливаются браузерной разведкой; автоматическое восстановление применяется даже при RECON_MODE=http. Katana при этом повторно не запускается, поскольку передача одних cookies потеряла бы состояние SPA.

Ограничения: same-origin сценарии; сторонние CDN могут быть заблокированы; неоднозначные формы, перекрывающие модальные окна и сложная навигация могут требовать доработки. HTTP-перенос требует cookies или наблюдаемого Authorization. API с другими механизмами сессии, IndexedDB-only состоянием, несколькими токенами или автоматической ротацией пока не обрабатываются универсально. Разведка собирает ссылки и GET API; полный захват POST/JSON-тел не реализован. Сбой браузера/проверки сессии даёт ошибку или incomplete, а не анонимный успех.

Живой локальный тест (создаёт только собственный HTTP-сервер):

```bash
PYTHONPATH=. .venv/bin/python tests/browser_smoke.py
```

Тест покрывает localStorage, sessionStorage, два аккаунта, восстановление при разведке и неверный пароль. Браузерный прогон требует Playwright. Для описанной проверки результат браузерного прогона не подтверждён.

## Быстрые команды Telegram

`/start` показывает основные сканеры и ссылку на `/modes`. `/modes` показывает:

- `/sqli_check <url> [тело POST]` — существующая проверка одной точки SQLi.
- `/xss_check <url>` — передаёт Dalfox только этот URL, без общей разведки/Katana. Scope ограничен origin и путём страницы; query может меняться для payload. Анализ внешних JS с другим путём также ограничен, поэтому покрытие DOM XSS ниже полного режима.
- `/idor_check <url>` — GET одного URL под A/B и анонимно, без обхода и подбора ID. Нужны два разных авторизованных аккаунта. Совпадение содержимого — кандидат, а не доказательство неправильных прав: приватность и владение проверяются вручную.

При передаче учётных данных автологин по-прежнему может обращаться к страницам входа и API проверки сессии. Быстрый режим ограничивает поиск целей, а не количество всех HTTP-запросов. Для анонимного XSS отправьте `-`. После изменения команд перезапустите процесс бота.
